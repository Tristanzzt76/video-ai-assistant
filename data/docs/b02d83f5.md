# H.264/AVC 编码详解

## H.264 编码原理

H.264（又称 AVC，Advanced Video Coding）是由 ITU-T 与 MPEG 联合制定的视频编码标准（ISO/IEC 14496-10），发布于 2003 年，至今仍是互联网视频的主流编码格式。

H.264 通过以下核心技术实现高压缩率：

- **帧内预测（Intra Prediction）**：利用同一帧内相邻块的像素预测当前块，减少空间冗余
- **帧间预测（Inter Prediction）**：利用前后帧的运动信息预测当前帧，减少时间冗余
- **变换编码（DCT）**：将残差信号从空间域变换到频率域，能量集中于低频
- **量化（Quantization）**：丢弃高频细节，控制码率与质量的权衡
- **熵编码（CABAC/CAVLC）**：对量化系数进行无损压缩，CABAC 效率更高

编码流程：原始帧 → 预测 → 残差计算 → DCT 变换 → 量化 → 熵编码 → 码流输出。

## 帧类型

### I 帧（Intra Frame / IDR Frame）

- **定义**：完全独立编码的帧，不依赖任何其他帧，可作为随机访问点
- **IDR 帧**（Instantaneous Decoder Refresh）：特殊的 I 帧，通知解码器清空参考帧缓冲，之后的帧不会引用 IDR 之前的帧
- **特点**：压缩率最低，数据量最大（通常是 P 帧的 5~10 倍）
- **应用**：视频开头、随机跳转点、HLS 切片开始处必须是 IDR 帧

### P 帧（Predictive Frame）

- **定义**：使用前面已解码的帧（参考帧）进行运动补偿预测
- **特点**：只存储与参考帧的差异，压缩率较高
- **依赖**：解码 P 帧前必须先解码其所有参考帧
- **典型大小**：约为 I 帧的 1/3~1/5

### B 帧（Bi-directional Predictive Frame）

- **定义**：同时参考前方和后方的帧进行双向预测
- **特点**：压缩率最高，但增加编解码延迟（需要缓冲后续帧）
- **延迟影响**：直播场景通常禁用 B 帧以降低延迟
- **典型大小**：约为 I 帧的 1/8~1/10

## GOP（Group of Pictures）

GOP 是从一个 I 帧到下一个 I 帧之前的所有帧的集合，是视频编码的基本单元。

### GOP 结构示例

```
I B B P B B P B B P B B I ...
|<------------- GOP ------------->|
```

### 开放 GOP vs 封闭 GOP

| 类型 | 说明 | 应用场景 |
|------|------|----------|
| 封闭 GOP（Closed GOP） | GOP 内的帧只参考本 GOP 内的帧，IDR 帧重置参考帧缓冲 | HLS 切片（每个切片独立可解码） |
| 开放 GOP（Open GOP） | 第一个 I 帧后的 B 帧可能参考前一 GOP 的帧 | 蓝光、文件存储（更高压缩率） |

### GOP 大小的影响

| GOP 大小 | 压缩率 | 随机访问 | 切换延迟 | 典型场景 |
|----------|--------|----------|----------|----------|
| 小（1~2s） | 低 | 快 | 短 | 直播低延迟 |
| 中（2~4s） | 中 | 中 | 中 | HLS 点播 |
| 大（8~10s） | 高 | 慢 | 长 | 高清存档 |

**最佳实践**：HLS/DASH 流媒体场景推荐 GOP = 切片时长，确保每个切片包含完整 GOP，支持独立解码。

## 码率控制

### CBR（Constant Bitrate，恒定码率）

- 输出码率保持恒定（如 2 Mbps）
- 场景复杂时降低质量，场景简单时浪费带宽
- 适用于：实时直播、带宽严格受限场景
- 编码参数：`-b:v 2M -minrate 2M -maxrate 2M -bufsize 4M`

### VBR（Variable Bitrate，可变码率）

- 根据内容复杂度动态调整码率，在目标平均码率约束下运行
- 复杂场景（运动、纹理多）分配更多码率，简单场景节省码率
- 适用于：点播、离线转码
- 编码参数：`-b:v 2M -maxrate 3M -bufsize 6M`

### CRF（Constant Rate Factor，恒定质量因子）

- 以固定的主观质量为目标，码率随内容动态变化
- CRF 值范围 0~51（H.264），值越小质量越高、文件越大
  - 0：无损
  - 18：视觉无损
  - 23：默认值（良好质量）
  - 28：可接受质量下限
- 适用于：归档、高质量点播
- 编码参数：`-crf 23`

### 对比

```
质量保证：CRF > VBR > CBR
码率稳定：CBR > VBR > CRF
直播适用：CBR > VBR，CRF 不适用
```

## Profile 与 Level

### Profile（编码特性集合）

| Profile | 特性 | 适用场景 |
|---------|------|----------|
| Baseline | 无 B 帧，无 CABAC，简单容错 | 低延迟直播、旧移动设备 |
| Main | 支持 B 帧，支持 CABAC | 标清/高清内容 |
| High | 8x8 变换，量化矩阵自定义 | 蓝光、高清流媒体（主流选择） |
| High 10 | 10bit 色深 | HDR 内容 |

### Level（分辨率/码率上限）

Level 限制了最大分辨率、帧率和码率的组合。常用 Level：

| Level | 最大分辨率 @ 帧率 | 最大码率（High Profile） |
|-------|-------------------|--------------------------|
| 3.0 | 720x480 @ 30fps | 10 Mbps |
| 3.1 | 1280x720 @ 30fps | 14 Mbps |
| 4.0 | 1920x1080 @ 30fps | 20 Mbps |
| 4.1 | 1920x1080 @ 30fps | 50 Mbps |
| 5.1 | 4096x2304 @ 30fps | 240 Mbps |

## 关键编码参数

```bash
# FFmpeg H.264 编码示例
ffmpeg -i input.mp4 \
  -c:v libx264 \
  -profile:v high \       # Profile: baseline/main/high
  -level 4.1 \            # Level
  -crf 23 \               # 质量因子（恒质量模式）
  -preset medium \        # 编码速度/压缩率权衡（ultrafast/fast/medium/slow/veryslow）
  -r 30 \                 # 帧率（fps）
  -s 1920x1080 \          # 分辨率
  -g 60 \                 # GOP 大小（keyframe interval = fps × 期望秒数）
  -keyint_min 60 \        # 最小关键帧间隔
  -sc_threshold 0 \       # 禁止场景切换插入额外关键帧
  -b:v 2M \               # 目标码率（VBR/CBR 模式）
  -c:a aac -b:a 128k \    # 音频编码
  output.mp4
```

## 转码（Transcoding）vs 传码（Transmuxing）

### 转码（Transcoding）

- **定义**：对视频流进行解码后重新编码，改变编码参数
- **操作**：解码 → 处理 → 重新编码
- **用途**：改变分辨率、码率、编码格式（H.264 → H.265）、添加水印
- **代价**：CPU 密集，有质量损失（每次编解码引入量化误差）
- **延迟**：高（需要完整的编解码流程）

### 传码（Transmuxing）

- **定义**：只改变容器格式，不重新编码媒体流
- **操作**：解析容器 → 提取裸流 → 写入新容器
- **用途**：MP4 → HLS（.ts 切片）、RTMP 流 → HLS、FLV → MP4
- **代价**：极低 CPU 消耗，无质量损失
- **延迟**：低（近实时）

### 对比

```
操作          转码                    传码
编码格式      可更改                  不变
媒体质量      有损失                  无损失
CPU 消耗      高                     极低
典型场景      多码率转换、格式转换    直播切片、容器转换
```

**实践场景**：直播服务器将 RTMP 推流转为 HLS 分发，通常是传码（仅改变容器）；而生成多码率 HLS 流需要对原流进行多次转码。
