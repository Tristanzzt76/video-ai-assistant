# 视频质量评估详解

## 客观质量指标

### PSNR（峰值信噪比，Peak Signal-to-Noise Ratio）

PSNR 是最经典的视频质量客观指标，通过对比原始帧与压缩帧的像素差异计算：

```
MSE = (1/MN) × Σ Σ [I(i,j) - K(i,j)]²
PSNR = 10 × log10(MAX² / MSE)
```

其中 MAX 为像素最大值（8bit 图像为 255），MSE 为均方误差。

| PSNR 值 | 主观质量感受 |
|---------|------------|
| > 40 dB | 极高质量，肉眼几乎无法区分 |
| 35~40 dB | 高质量 |
| 30~35 dB | 可接受质量 |
| < 30 dB | 明显失真 |

**局限性**：PSNR 仅基于像素误差，与人眼主观感受相关性较低。结构性失真（模糊、块效应）与噪声导致的 PSNR 下降，主观感受可能完全不同。

---

### SSIM（结构相似性，Structural Similarity Index）

SSIM 模拟人眼对亮度、对比度和结构的感知，计算公式：

```
SSIM(x, y) = [l(x,y)]^α × [c(x,y)]^β × [s(x,y)]^γ
```

其中：
- `l(x,y)`：亮度比较
- `c(x,y)`：对比度比较
- `s(x,y)`：结构比较

**取值范围**：[-1, 1]，1 表示完全相同。

| SSIM 值 | 质量评价 |
|---------|---------|
| > 0.95 | 优秀 |
| 0.90~0.95 | 良好 |
| 0.80~0.90 | 可接受 |
| < 0.80 | 较差 |

**优势**：比 PSNR 更接近人眼感知，对结构性失真更敏感。  
**局限性**：对时序信息不敏感，无法很好评估运动估计误差。

---

### VMAF（Video Multi-method Assessment Fusion）

VMAF 由 Netflix 于 2016 年开发，是目前业界最广泛使用的视频质量评估指标。

**原理**：
1. 提取多个底层特征（VIF、DLM、Motion）
2. 训练 SVM/神经网络模型，融合特征
3. 输出 0~100 的质量分数

**特征组成**：
- **VIF（Visual Information Fidelity）**：基于信息论的图像保真度
- **DLM（Detail Loss Metric）**：细节损失度量
- **Motion**：运动幅度（运动大时人眼对失真更不敏感）

**VMAF 分数参考**：

| 分数 | 质量 |
|------|------|
| 93~100 | 参考级质量 |
| 75~93 | 高质量（流媒体良好体验） |
| 60~75 | 可接受 |
| < 60 | 质量较差 |

**使用工具**：
```bash
# FFmpeg + libvmaf 计算 VMAF
ffmpeg -i distorted.mp4 -i reference.mp4 \
  -lavfi "[0:v][1:v]libvmaf=model_path=/usr/share/model/vmaf_v0.6.1.json" \
  -f null -
```

**适用场景**：编码参数调优、转码质量验证、不同编码方案对比。

## 主观质量：MOS 评分

MOS（Mean Opinion Score，平均意见分）是通过人工主观评测获得的质量分数：

- 评测员观看原始视频和压缩视频，按 1~5 分打分
- MOS = 所有评测员分数的算术平均值

| MOS 分 | 质量 | 可接受程度 |
|--------|------|-----------|
| 5 | 优秀（Excellent） | 完全无感知失真 |
| 4 | 良好（Good） | 轻微失真，不影响体验 |
| 3 | 一般（Fair） | 中等失真，稍有影响 |
| 2 | 较差（Poor） | 明显失真，影响体验 |
| 1 | 差（Bad） | 严重失真，难以接受 |

客观指标与 MOS 的相关性：VMAF > SSIM > PSNR（与人眼感知的相关程度）。

## 影响视频质量的因素

### 分辨率

| 分辨率 | 常见名称 | 像素数 |
|--------|---------|--------|
| 3840×2160 | 4K UHD | 8,294,400 |
| 1920×1080 | 1080p FHD | 2,073,600 |
| 1280×720 | 720p HD | 921,600 |
| 854×480 | 480p SD | 409,920 |
| 640×360 | 360p | 230,400 |

高分辨率在小屏幕上收益递减，PPI（每英寸像素数）决定实际清晰感知。

### 帧率（FPS）

- **24fps**：电影感，常用于影视内容
- **30fps**：标准电视，直播主流
- **60fps**：游戏、体育赛事，运动流畅感强
- **120fps**：高帧率（HFR），新一代高端内容

帧率提升使运动更流畅，但同等质量下码率增加约 50%~100%。

### 码率

码率是决定视频文件大小和传输需求的核心参数：

| 分辨率 | 推荐码率（H.264） | 推荐码率（H.265） |
|--------|----------------|----------------|
| 360p | 400~800 kbps | 200~400 kbps |
| 720p | 1.5~3 Mbps | 750k~1.5 Mbps |
| 1080p | 3~6 Mbps | 1.5~3 Mbps |
| 4K | 15~25 Mbps | 8~12 Mbps |

### 编码参数对质量的影响

- **CRF/QP**：直接控制量化步长，越低质量越高
- **Preset（编码速度）**：`veryslow` 比 `ultrafast` 在相同码率下 VMAF 高 5~15 分
- **B 帧数量**：更多 B 帧 → 更高压缩率 → 相同码率下质量更好
- **参考帧数（ref）**：增加参考帧提升预测精度，但增加解码复杂度

## 画质敏感度：MVQ（Mobile Video Quality）

MVQ 是面向移动端视频质量的综合评估体系，考虑移动场景特殊性：

- **设备屏幕差异**：低端机小屏 vs 高端机大屏，相同分辨率感知不同
- **网络波动**：移动网络不稳定，需要动态 ABR 策略
- **用户行为**：快滑（快速滑动视频）vs 精看，不同场景质量需求不同

**画质敏感度分层**：
- **高敏感**：用户对画质变化感知明显，倾向于高质量流（高分辨率/高码率）
- **低敏感**：用户对画质变化感知不明显，可接受低质量流以换取流畅播放

**应用场景**：根据用户画质敏感度个性化 ABR 策略，高敏感用户倾向于高码率流，低敏感用户优先保证流畅性（低码率稳定流）。

## ABR 自适应码率算法

ABR（Adaptive Bitrate）算法决定在多码率流中何时切换到哪个码率级别。

### 吞吐量算法（Throughput-based）

- **原理**：根据最近几个切片的实际下载速度估算当前带宽，选择不超过带宽的最高码率
- **优点**：简单直接，对网络变化响应快
- **缺点**：网络吞吐量估计有误差，易产生频繁切换（"抖动"）
- **代表实现**：HLS.js 默认算法

### Buffer-based 算法（BBA）

- **原理**：根据当前播放缓冲区大小选择码率
  - 缓冲区充足 → 升级到高码率
  - 缓冲区不足 → 降级到低码率
- **优点**：对网络估计误差不敏感，切换更稳定
- **缺点**：响应网络变化慢（需要等缓冲区变化才反应）
- **代表实现**：Netflix BOLA

### 混合算法（Hybrid）

结合吞吐量估计和缓冲区状态：

```
目标码率 = f(带宽估计, 缓冲区水位, 切换历史)
```

- **MPC（Model Predictive Control）**：预测未来带宽，选择最优码率序列
- **Pensieve（强化学习）**：使用神经网络学习最优 ABR 策略
- **代表实现**：dash.js 的 `LoLP` 算法、Shaka Player

## 卡顿指标

### Buffering Ratio（卡顿率）

```
卡顿率 = Σ缓冲等待时间 / 总播放时间 × 100%
```

行业标准：卡顿率 > 1% 对用户体验有明显负面影响，目标值 < 0.5%。

### TTFF（Time To First Frame，首帧时间）

从用户触发播放到第一帧画面显示的时间，包含：
- DNS 解析时间
- TCP 连接时间
- HTTP 请求时间
- 初始缓冲时间（下载足够数据供解码）
- 解码首帧时间

目标：移动端 TTFF < 1 秒，桌面端 < 500ms。

### 其他播放质量指标

| 指标 | 说明 |
|------|------|
| 播放成功率 | 请求播放后成功播放的比例 |
| 卡顿次数 | 单次播放中缓冲等待的次数 |
| 平均码率 | 整个播放会话的平均下载码率 |
| 码率切换次数 | ABR 切换频率，过高影响体验 |
| 错误率 | 播放中断（网络错误、解码错误）的比例 |

## 质量评估流程

### 编码质量评估

```
1. 准备参考视频（原始无损素材）
2. 使用不同编码参数生成多个压缩版本
3. 计算 VMAF/SSIM/PSNR（per-frame 和整体均值）
4. 绘制码率-质量曲线（Rate-Distortion Curve）
5. 确定各分辨率的最优码率梯子（Bitrate Ladder）
```

### 码率梯子（Bitrate Ladder）设计

Netflix 提出 Per-title Encoding（按内容优化），不同内容使用不同码率梯子：

```
动画片（低复杂度）：360p@400k, 720p@1.2M, 1080p@2.5M
体育赛事（高运动）：360p@800k, 720p@2.5M, 1080p@5M
```

**评估工具**：
```bash
# 批量评估脚本示例
for bitrate in 500k 1M 2M 4M; do
  ffmpeg -i input.mp4 -b:v $bitrate -c:v libx264 output_${bitrate}.mp4
  ffmpeg -i output_${bitrate}.mp4 -i input.mp4 \
    -lavfi libvmaf=log_path=vmaf_${bitrate}.json \
    -f null -
done
```

### 线上质量监控

- **客户端 SDK**：上报 TTFF、卡顿率、码率等数据到监控平台
- **A/B 测试**：对比不同编码参数/ABR 策略的用户体验指标
- **实验室测试**：定期使用自动化工具对典型内容运行 VMAF 评估
